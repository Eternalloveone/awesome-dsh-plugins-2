# DSH 插件安装安全指南

DeepSeek Harness 的插件可以向 Agent 暴露工具、注入 Web UI、访问文件系统、调用网络服务，或挂载到 Cordis 的共享上下文。官方文档说明，Profile 不仅会组合 Bundle，也会保存已安装的外部插件与用户补丁。[1] 因此，安装插件应被视为一次**本地代码执行与权限扩展**，而不是普通网页主题安装。

> **本目录的“已核验”仅表示项目公开展示了 DSH 原生挂载证据与安装路径。它不表示该项目已经过完整安全审计、稳定性测试或作者身份认证。**

## 安装前的最低检查

| 检查项 | 应做什么 | 为什么 |
| --- | --- | --- |
| 锁定来源 | 使用发布 tag、commit SHA 或可信 npm 包版本；记录来源 URL | 默认分支可以随时改变 |
| 阅读入口 | 查看 `package.json`、`dsh.plugin.json`、`cordis.patch.yml`、`apply` 入口与依赖 | 可确认它实际挂载了哪些服务和工具 |
| 审计安装脚本 | 检查 `preinstall`、`install`、`postinstall` 及 `prepare` | 包管理器生命周期脚本可执行任意本地命令 |
| 最小权限 | 单独创建测试 Profile；使用无生产数据的工作目录与受限 API Key | 减小失控工具调用和数据外泄影响 |
| 外发检查 | 确认提示词、代码、图片、会话日志及工具结果会发往哪些端点 | 视觉、搜索、记忆与 IM 插件通常会发送数据 |
| 记录回退 | 安装前导出 Profile 配置；记录新增依赖与 patch | 预览期 API 不稳定，需要快速移除或回滚 |

## 高风险权限矩阵

| 权限面 | 典型项目 | 主要风险 | 建议控制 |
| --- | --- | --- | --- |
| 已登录浏览器 | `dsh-better-browser` | Cookie、会话、表单填写、上传与页面操作 | 使用专用浏览器 Profile；不要登录资金、生产或个人敏感账户；开启人工审批 |
| SSH / SFTP / 远程命令 | `dsh-ssh`、`jumpserver-dsh` | 远程代码执行、文件读取/覆盖、密钥泄露 | 使用专用低权限用户、显式 known-hosts、跳板 ACL、目录白名单与审计 |
| IM 渠道 | `dsh-lark`、`dsh-lark-bridge` | 未授权人员通过消息触发 Agent；会话外泄 | 限制用户/群组 allowlist；要求审批；禁用不可信私聊 |
| 文件和笔记 | `dsh-wikilink`、技能、自动化 | 工作区或聊天资料被注入提示词或上传 | 仅挂载必要目录；检查内容过滤和数据留存 |
| 外部 API | 搜索、视觉、记忆、费用插件 | API Key 泄露、数据传输、不可控费用 | 环境变量存储密钥；每个插件单独 Key；设置限额与告警 |
| 客户端注入与本机 CLI | UI、通知、VS Code、TUI | 浏览器权限、命令参数滥用、输出泄露 | 仅使用可信来源；检查注入模块；明确编辑器可执行路径 |

## 推荐的隔离测试流程

先通过 `dsh --profile <name> --dump-config` 导出目标配置，建立新的测试 Profile，再安装单个插件。检查新增依赖、`cordis.patch.yml` 配置行和 Web Client 注入项；确认无异常脚本后启动并进行最小功能测试。只有在数据流向、工具权限与行为均符合预期时，再考虑移入常用 Profile。[1]

在离线或敏感环境中，应优先选择本地模型、本地 LM Studio、无云端同步的插件配置。需要浏览器、远程执行、IM 或第三方 API 的插件，必须将密钥、允许目标和人工确认策略放在 Profile 或环境层配置中，不能提交到 Git 仓库。

## 漏洞与恶意条目报告

如果发现本目录收录项目存在明显恶意行为、密钥暴露、供应链风险、误导性安装命令或错误分类，请不要在公开 issue 中粘贴密钥、内部 URL、会话内容或漏洞利用细节。请以可复现的最小证据说明问题，并标注项目地址、受影响版本、风险类型与公开披露状态。维护者会将条目降级为观察名单、添加警告或移除。
